Testing search

Feature tests proving the search box actually narrows the catalogue by title, author, and year, plus unit tests locking scopeSearch()'s three matching branches - and the non-matching and blank-term cases - down directly on the model.

Search has only ever been checked by hand so far: type something into the box, look at what comes back. This topic closes that gap the same way the last lesson's final topic did for reviews - tests for scopeSearch() itself, and tests for the route that actually uses it.

The scope, tested directly

Tests\Unit\BookTest already covers Book's factory, its relationships, and its own attributes. scopeSearch() is model logic too, so it belongs in the same file, called the same way topic 5.2's tinker session called it - directly on the model, no HTTP involved:

public function test_the_search_scope_matches_a_books_title_an_authors_name_or_its_year(): void
{
    $book = Book::factory()->create(['title' => 'Dune', 'year' => 1965]);
    $book->authors()->attach(Author::factory()->create(['name' => 'Frank Herbert']));

    $this->assertTrue(Book::search('Dune')->exists());
    $this->assertTrue(Book::search('Herbert')->exists());
    $this->assertTrue(Book::search('1965')->exists());
}

Book::search('Dune') is the same static-call shorthand Eloquent scopes have supported since topic 5.1 - it reads as if search() were a real method on Book itself, though scopeSearch() is what actually runs. exists() is new: it asks the database "does at least one row match this query" without pulling any of them back, the cheapest possible way to check a scope actually narrowed things down to something rather than nothing. One book, three searches, three branches of the same where(function ...) { ... } closure from topic 5.2 - title, author, and year all proven to reach the same row.

Proving a match works isn't the whole claim a search makes, though - a search that matched everything would pass the test above too:

public function test_the_search_scope_finds_nothing_for_a_non_matching_term(): void
{
    Book::factory()->create(['title' => 'Dune', 'year' => 1965]);

    $this->assertFalse(Book::search('zzz')->exists());
}

public function test_the_search_scope_with_a_blank_term_returns_every_book(): void
{
    Book::factory()->count(3)->create();

    $this->assertSame(3, Book::search(null)->count());
    $this->assertSame(3, Book::search('')->count());
}

The first proves a term that matches nothing really does come back empty - the missing half of "search works" that only checking matches would let slip past unnoticed. The second locks down the guard both topics 5.1 and 5.2 built the whole scope around: null (no search key in the query string at all) and '' (the box submitted empty) both have to leave every book visible, not narrow the catalogue down to zero. That guard has been true since topic 5.1's very first version of scopeSearch() - this is the first time anything actually checks it.

The route, tested through a real request

Tests\Feature\BookTest already has a request-level test for books.index from Lesson 2's testing topic - listing books with no search at all. Four more prove the search box itself, one per matching branch and one for the miss:

public function test_the_index_page_search_matches_a_books_title(): void
{
    $user = User::factory()->create();
    Book::factory()->create(['title' => 'Dune']);
    Book::factory()->create(['title' => 'Some Other Title']);

    $response = $this->actingAs($user)->get(route('books.index', ['search' => 'Dune']));

    $response->assertOk();
    $response->assertSee('Dune');
    $response->assertDontSee('Some Other Title');
}

route('books.index', ['search' => 'Dune']) builds /books?search=Dune directly - the same URL submitting the form produces, without a browser in the way. assertDontSee() is the half test_the_index_page_lists_books back in Lesson 2 never needed and this test does: proof that the other book, the one that shouldn't match, actually disappeared from the page rather than just happening not to be checked for. assertSee() alone would still pass if search silently did nothing at all.

Author and year repeat the same shape, over the two branches topic 5.2 added:

public function test_the_index_page_search_matches_an_authors_name(): void
{
    $user = User::factory()->create();
    $book = Book::factory()->create(['title' => 'Dune']);
    $book->authors()->attach(Author::factory()->create(['name' => 'Frank Herbert']));
    Book::factory()->create(['title' => 'Some Other Title']);

    $response = $this->actingAs($user)->get(route('books.index', ['search' => 'Herbert']));

    $response->assertOk();
    $response->assertSee('Dune');
    $response->assertDontSee('Some Other Title');
}

public function test_the_index_page_search_matches_a_year(): void
{
    $user = User::factory()->create();
    Book::factory()->create(['title' => 'Dune', 'year' => 1965]);
    Book::factory()->create(['title' => 'Some Other Title', 'year' => 1999]);

    $response = $this->actingAs($user)->get(route('books.index', ['search' => '1965']));

    $response->assertOk();
    $response->assertSee('Dune');
    $response->assertDontSee('Some Other Title');
}

Neither test asserts anything about scopeSearch() directly - from the route's side, all that matters is that the right book ends up on the page and the wrong one doesn't. The unit tests above already cover why that happens; these prove the whole request/response cycle actually delivers it.

The empty state, and the box that remembers what you typed

Two more small claims from topics 5.1 and 5.2, each easy to break without a test noticing:

public function test_the_index_page_shows_a_message_for_a_non_matching_search(): void
{
    $user = User::factory()->create();
    Book::factory()->create(['title' => 'Dune']);

    $response = $this->actingAs($user)->get(route('books.index', ['search' => 'zzz']));

    $response->assertOk();
    $response->assertDontSee('Dune');
    $response->assertSee('No books match "zzz".');
}

public function test_the_search_box_repopulates_with_the_current_search_term(): void
{
    $user = User::factory()->create();
    Book::factory()->create(['title' => 'Dune']);

    $response = $this->actingAs($user)->get(route('books.index', ['search' => 'Dune']));

    $response->assertSee('value="Dune"', false);
}

assertSee('No books match "zzz".') checks the exact wording books/index.blade.php's @forelse/@empty branch chose specifically for a search with no results - proof the view actually tells the two empty states apart, not just that some message shows up. The second test's false argument turns off assertSee()'s default HTML-escaping of the text being searched for - needed here because the assertion is checking for a literal HTML attribute (value="Dune"), not text a person reading the page would see, and value="Dune" written into a test as plain text would otherwise get escaped into something that never actually appears in the response.
